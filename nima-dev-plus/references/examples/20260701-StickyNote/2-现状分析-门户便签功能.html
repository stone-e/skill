五、风险点
低风险 — 实时保存防抖
触发条件：用户快速连续输入。影响：可能产生较多请求。
建议：前端防抖 500ms，后端接口幂等（update 按 id 更新）。
低风险 — 用户数据隔离
触发条件：后端查询未正确过滤 user_id。影响：可能看到其他用户便签。
建议：Service 层 list 方法自动注入当前用户 ID 作为查询条件（参考 SsoClientService.listPortalApps 的模式）。
低风险 — 内容长度
触发条件：用户输入超长文本。影响：数据库存储压力。
建议：前端 textarea 限制最大长度（如 5000 字符），后端 content 字段使用 TEXT 类型（最大 65535 字节）。
中风险 — 并发编辑
触发条件：同一用户在两个设备上同时编辑同一条便签。影响：后覆盖前。
建议：本期不做乐观锁，接受"最后写入胜出"策略（便签是个人工具，并发概率极低）。
六、数据流

6.1 创建便签

前端点击"新建" → POST /busi/stickyNote → Controller → Service.beforeCreate → Mapper.insert → DB

6.2 编辑便签（实时保存）

前端编辑内容 → 防抖 500ms → PUT /busi/stickyNote → Controller → Service.afterUpdate → Mapper.updateById → DB

6.3 查询便签列表

弹窗打开 → GET /busi/stickyNote/page → Controller → Service.list（自动注入 user_id 条件）→ DB

6.4 删除便签

前端点击删除 → ElMessageBox 确认 → DELETE /busi/stickyNote/batchDelete → Controller → Service.delete（逻辑删除）→ DB
