# 原型确认 — 条件触发

## 目标

通过可交互原型或代码片段，让用户确认设计方向是否正确，避免开发完成后返工。

## 触发决策树

```
研发设计完成后，Agent 评估：

  需求是否涉及用户界面变更？
    ├── 否 → 是否需要用户交互流程确认？
    │         ├── 否 → ⏭️ 跳过原型，直接进入开发交付
    │         └── 是 → 🔶 生成交互原型
    └── 是 → 是否为新页面/新组件？
              ├── 否（微调现有页面）→ 🔶 生成代码片段+说明
              └── 是 → 🔶 生成可运行 HTML 原型

  额外触发条件（满足任一即触发）：
    - 需求描述存在歧义，有多种实现可能
    - 涉及多步骤用户操作流程
    - 用户明确要求"先看看效果"
    - 跨模块/外部系统对接，接口契约需确认
```

## 原型输出形式（按场景分级）

| 场景 | 原型形式 | 说明 | 模板 |
|------|---------|------|------|
| **A. 纯后端逻辑改动** | 代码片段 + 文本说明 | 展示修改前后代码 diff 和逻辑说明 | `code-snippet.html` |
| **B. 接口变更** | 接口契约文档 + 示例 JSON | 展示请求/响应格式、字段变更 | `code-snippet.html` |
| **C. 前端微调** | 代码片段 + 效果描述 | 展示组件修改 + 文字描述预期效果 | `code-snippet.html` |
| **D. 新页面/新流程** | **可运行 HTML 原型** | 独立 HTML 文件，浏览器打开即可交互 | `prototype.html` |
| **E. 全栈新功能** | **可运行 HTML 原型 + 接口 Mock** | 前端原型 + 模拟后端数据 | `prototype.html` |

## HTML 原型规范（D/E 场景）

### 必备元素

1. **原型标注水印** — 顶部显示"原型预览 — 用于确认设计方向"
2. **交互元素高亮** — 可点击区域用虚线框标注
3. **固定底部操作栏** — "确认此设计" / "需要修改" 按钮
4. **响应式布局** — 适配桌面/移动端
5. **Mock 数据** — 前端原型使用模拟数据演示

### 生成后操作

1. 保存 HTML 文件到 `{storyDir}/3P-原型确认-{storyNameCN}.html`
2. 用系统默认浏览器打开：`start "" "{filePath}"`
3. 向用户说明："原型已打开，请体验后在聊天中告诉我设计方向是否正确"

> ⚠️ **重要**：HTML 是给人看的展示载体，不是交互界面。禁止在 HTML 中添加虚假交互按钮（如 onclick 弹窗）。用户反馈必须通过 Agent chat 进行。

## 用户反馈处理（通过 Agent chat）

> HTML 原型页面底部有反馈引导区，告诉用户在聊天中反馈。

| 用户反馈（在 chat 中） | 处理方式 |
|----------------------|---------|
| "设计正确" / "没问题" / "可以" | 标记原型确认完成，进入开发交付 |
| "需要修改" + 具体意见 | 回到研发设计阶段，根据意见修改设计，重新生成原型 |
| "这里改一下..." | 直接修改原型 HTML，重新展示确认 |
| "重新生成" | 重新设计并生成新的原型 HTML |

## 跳过原型的情况

- 纯后端逻辑调整（改个字段、加个校验）
- 用户明确说"不用看原型，直接做"
- 需求内迭代的小功能追加（已有上下文）

跳过时：在 `context.json` 中标记 `phases.原型确认.skipped = true`

## 完成后更新

- `context.json`：`currentPhase = 开发交付`，`phases.原型确认.done = true`
- 驾驶舱 HTML：更新进度、产出清单、修改记录
