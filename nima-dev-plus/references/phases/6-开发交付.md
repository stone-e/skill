# 开发交付 — 快速/完整共用

## 目标

按设计文档和编码规范，通过**多轮小步迭代**完成代码实现。

## 核心原则

小步先行的精髓是**多轮次逐步收敛**——每轮有明确焦点，每轮先主动交互再继续。

**编码规范请严格遵循**：`references/coding-standards.md`

---

## 执行流程总览

```
第1轮：骨架先行 → 交互确认 →
第2轮：内容填充 → 闭环收口 →
第3轮：复盘验证 → 加固边界 →
第4轮：风险排查 → 结果展示
```

每轮完成后更新 `context.json` 的 `todos` 和驾驶舱的修改记录。

---

## 第1轮：骨架先行与流程验证

**焦点**：先搭骨架再填肉，确保方向正确再深入。

| 步骤 | 内容 | 产出 |
|------|------|------|
| 1.1 复查设计 | 对照设计文档逐条核对待实现列表 | 设计确认清单 |
| 1.2 骨架编码 | 编写方法签名、接口定义、实体/DTO、Controller 空壳、Service 接口。方法体可写伪代码或 TODO 注释 | 框架级代码 |
| 1.3 流程验证 | 检查调用链是否完整：Controller → Service → Mapper → DB | 流程确认 |
| 1.4 用户交互 | **主动向用户展示骨架和流程**，确认方向无误 | 用户反馈 |

**全栈模式**：

| 步骤 | 前端内容 | 产出 |
|------|---------|------|
| 1.2F 前端骨架 | 创建页面/组件骨架、路由配置、API 调用封装、TypeScript 类型定义 | 前端框架代码 |
| 1.3F 前端验证 | 检查：路由可达 → 组件渲染 → API 调用链路 → 状态管理流转 | 前端流程确认 |

**通过标准**：用户确认方向无误，或根据反馈调整后继续。

---

## 第2轮：内容填充与闭环收口

**焦点**：基于项目实际代码风格填充完整实现，并做跨文件一致性检查。

| 步骤 | 内容 | 产出 |
|------|------|------|
| 2.1 内容填充 | 将骨架/伪代码替换为完整实现。严格遵循 `coding-standards.md`，复用项目已有工具类和编码习惯 | 完整代码 |
| 2.2 串联检查 | **主动串联所有改动文件**，检查接口调用关系、参数传递、返回值类型是否一致 | 一致性确认 |
| 2.3 收口检查 | 逐文件 Read 检查：① import 完整 ② 方法签名对齐 ③ 注解齐全 ④ 无编译级错误 | 自检清单 |

**全栈模式**：

| 步骤 | 前端内容 | 产出 |
|------|---------|------|
| 2.1F 前端填充 | 填充组件逻辑：表单绑定、事件处理、API 调用、状态管理、加载/错误状态处理 | 前端完整代码 |
| 2.2F 前后端串联 | 验证前后端接口对接：① 请求参数与后端 DTO 一致 ② 响应字段与前端类型一致 ③ 错误码处理匹配 ④ 分页/排序参数对齐 | 前后端一致性 |
| 2.3F 前端收口 | 逐文件检查：① import 完整 ② Props/Events 类型对齐 ③ 模板/JSX 语法正确 ④ 样式引用有效 | 前端自检清单 |

**通过标准**：代码文件间调用关系一致，无编译级遗漏。无需用户确认，直接进入第3轮。

---

## 第3轮：复盘验证与边界加固

**焦点**：重新理解需求，验证实现是否完整覆盖，重点加固异常和边界。

| 步骤 | 内容 | 产出 |
|------|------|------|
| 3.1 需求复盘 | **重新完整阅读需求文档**，逐条对照已实现的功能 | 需求覆盖矩阵 |
| 3.2 边界检查 | 逐项确认：①空值边界 ②分页边界 ③状态非法 ④权限越界 ⑤数据不存在 ⑥重复操作 ⑦并发冲突 | 边界清单 |
| 3.3 异常加固 | 补齐异常处理：①参数校验异常 ②业务异常 ③系统异常 ④外部依赖超时/熔断 | 异常处理代码 |
| 3.4 编译验证 | `mvn compile` 或对应构建命令验证无编译错误 | 编译通过 |

**全栈模式**：

| 步骤 | 前端内容 | 产出 |
|------|---------|------|
| 3.1F 前端复盘 | 对照需求文档，逐条检查前端页面/组件是否覆盖所有用户操作路径 | 前端覆盖矩阵 |
| 3.2F 前端边界 | 检查前端边界：①表单校验 ②空数据展示 ③加载状态 ④网络错误 ⑤权限不足提示 ⑥重复提交防护 | 前端边界清单 |
| 3.4F 前端验证 | 执行前端构建验证：`npm run build` / `pnpm build` | 前端构建通过 |

**通过标准**：所有需求条目有代码覆盖，边界场景有处理逻辑，编译通过。

---

## 第4轮：风险排查与结果展示

**焦点**：自我发现隐藏问题，主动向用户展示分析结果。

| 步骤 | 内容 | 产出 |
|------|------|------|
| 4.1 隐藏风险扫描 | 审视代码中不易发现的问题：①多线程竞态 ②事务失效场景 ③ORM N+1 查询 ④大事务/长事务 ⑤逻辑删除/数据权限被绕过 ⑥租户隔离遗漏 | 风险清单 |
| 4.2 冲突点检查 | 检查本次改动与现有代码的潜在冲突：①是否修改公用工具类/基类 ②是否与其他开发中的需求冲突 ③是否有硬编码配置项 ④是否引入新依赖及版本冲突 | 冲突分析 |
| 4.3 结果展示 | **主动向用户输出完整报告**：①改动文件清单 ②风险分析结果 ③未完成/延期的 TODO ④测试验证建议 | 交付报告 |

**全栈模式**：

| 步骤 | 前端内容 | 产出 |
|------|---------|------|
| 4.1F 前端风险 | 检查前端风险：①内存泄漏 ②XSS 风险 ③状态管理污染 ④路由守卫遗漏 ⑤大数据列表性能 | 前端风险清单 |
| 4.2F 前端冲突 | 检查前端冲突：①是否修改公共组件/hooks ②是否与其他页面路由冲突 ③是否有硬编码 API 地址 ④是否引入新依赖 | 前端冲突分析 |
| 4.3F 全栈报告 | 交付报告中同时包含前后端：①后端改动文件清单 ②前端改动文件清单 ③前后端接口对接矩阵 ④全栈测试验证建议 | 全栈交付报告 |

**通过标准**：风险已识别并处理，报告已展示给用户，待确认项已标注。
