# 闭环反馈 — 仅完整模式

## 目标

确认交付物与设计一致，处理开发交付阶段遗留的待确认项。

## 执行步骤

1. 回顾第4轮交付的风险报告，逐条处理用户反馈
2. 重新检查未完成的 TODO（按分类：临时/技债/外部依赖/逻辑补全/暂不明确）
3. 检查设计文档与实际代码的差异，更新文档
4. 给出**测试验证建议**：
   - 正常路径测试
   - 边界参数测试
   - 异常路径测试
   - 涉及数据库、接口、状态流转时，说明验证数据和预期结果
5. 如有必要，回到研发设计或开发交付补充

## 全栈模式（devMode=全栈）

| 维度 | 后端验证 | 前端验证 |
|------|---------|---------|
| 接口验证 | API 请求/响应与设计文档一致 | 前端调用与后端实际接口一致 |
| 功能验证 | 业务逻辑正确、数据持久化正确 | 页面交互正确、状态流转正确 |
| 集成验证 | — | 前后端联调：从用户操作到数据落库的完整链路 |

## 全栈测试验证建议

- 前端组件单元测试（如适用）
- 前后端接口联调测试（Postman / 浏览器 DevTools）
- 端到端测试建议（用户操作 → 前端响应 → 后端处理 → 数据验证）

## 完成后更新

- `context.json`：`currentPhase = 总结`，`phases.闭环反馈.done = true`
- 驾驶舱 HTML：更新进度

## 功能自验证引导

闭环反馈完成后，Agent 应主动向用户展示以下询问：

```
闭环反馈已完成，所有文档和代码已交付。

是否启动【功能自验证】？
功能自验证将自动：
  1. 启动项目（前端 + 后端）
  2. 使用浏览器工具自主操作和验证功能
  3. 使用接口工具自主验证 API
  4. 发现问题自动记录并修复
  5. 多轮验证直到全部通过

⚠️ 建议切换到多模态模型（支持图片理解），以便 Agent 截图分析页面效果。

请选择：
[1] 启动功能自验证
[2] 跳过，直接进入总结
```

- 用户选择 [1] → `currentPhase = 功能自验证`，进入 `references/phases/12-功能自验证.md`
- 用户选择 [2] → `currentPhase = 总结`，`phases.功能自验证.skipped = true`
