# 总结 — 每次迭代完成后

## 目标

生成功能快照文档，记录当前需求空间的能力全貌。

## 总结的本质

- **不是生命周期结束**，而是"这一阶段功能做完了，记录下来"
- 产出**功能快照**：这个需求空间当前能做什么、做了什么
- 用途：
  1. **项目功能文档** — 给人查阅的正式功能说明
  2. **后续迭代的快速回忆** — 下次迭代时不用重新读代码
  3. **知识图谱节点** — 关键词关联的基础

## 触发时机

| 触发场景 | 说明 |
|---------|------|
| 初始需求完成后 | 生成总结 v1 |
| 需求内迭代完成后 | 生成总结 v2、v3... |
| 归档交付时 | 生成最终总结（完整版） |

## 总结文档内容结构

### 1. 需求元数据
- 需求号、名称、类型、模式、作者、分支
- 项目环境信息

### 2. 迭代历史

| 版本 | 时间 | 作者 | 描述 | 改动范围 |
|------|------|------|------|---------|
| v1 | 2026-07-02 | stone | 起始页基础功能完成 | 后端 5 文件 / 前端 3 文件 |
| v2 | 2026-07-03 | stone | 追加天气小工具 | 前端 2 文件 |
| v3 | 2026-07-05 | stone | 追加待办小工具 | 前端 2 文件 |

### 3. 功能清单

```
✅ [v1] 页面框架搭建
✅ [v1] 数据卡片展示
✅ [v1] 快捷导航入口
✅ [v2] 天气小工具
✅ [v3] 待办事项小工具
```

### 4. 技术架构
- 技术栈
- 目录结构
- API 清单
- 数据库变更记录

### 5. 交付统计
- 后端改动文件数 / 新增代码行数
- 前端改动文件数 / 新增代码行数
- 数据库变更（DDL 条数）
- 新增接口数
- 风险已处理数 / 待确认数

### 6. 已知限制与待完善
- 遗留 TODO
- 待确认项
- 技债

## 文件名规则

`SUM-总结-{storyNameCN}-{版本号}.html`

示例：
- `SUM-总结-起始页功能-1.html`
- `SUM-总结-起始页功能-2.html`
- `SUM-总结-起始页功能-3.html`

## 模板

`references/html-templates/summary.html`

## 完成后更新

- `context.json`：更新当前迭代的 `summary` 字段
- `context.json`：更新 `keywords` 字段（追加新需求特征关键词）
- 驾驶舱 HTML：更新总结区内容

> 关键词是机器数据，仅存储在 context.json，不生成独立 HTML。
> 关键词必须是**需求特征**（业务域、功能模式、用户场景、业务概念），不要包含技术栈、模块路径等实现细节。
