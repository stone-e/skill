# 归档交付 — 三模式共用

## 目标

需求空间完结，生成最终交付物，合并或提交。

## 执行步骤

### 步骤 1：最终确认

1. 检查所有迭代是否已完成（无未完成的 phases）
2. 检查所有 TODO 状态（done 或明确标记为延期）
3. 确认无遗留风险或已标注为已知限制
4. **数据一致性验证**：驾驶舱 HTML 中的核心变量、项目环境、阶段进度必须与 context.json 完全一致

### 步骤 2：生成最终总结文档

- 汇总所有迭代的功能清单
- 生成完整的交付统计
- 产出最终版 `SUM-总结-{storyNameCN}-FINAL.html`

### 步骤 3：确保关键词数据完整

- 汇总全部关键词到 `context.json` 的 `keywords` 字段（业务/功能/技术/模块）
- 更新 `context.json` 的 `relatedStories` 关联需求列表
- 不生成独立 HTML 文件（关键词是给 Agent 做知识图谱查询用的机器数据）

### 步骤 4：锁定驾驶舱

- 将驾驶舱 HTML 标记为"已归档"
- 更新进度为 100%
- 锁定修改记录（只读）

### 步骤 5：Git 操作（经用户确认）

- 提交代码
- 合并分支（如用户要求）
- 推送远程（如用户要求）

### 步骤 6：记忆持久化

将以下信息保存到用户记忆：
- 需求空间的完整上下文
- 最终技术架构
- 关键词索引
- 经验教训

## 全栈模式

- 前后端代码同时提交/合并
- 确认前后端接口版本一致
- 提供完整的前后端联调验证清单
- 如有前端部署，说明构建和部署步骤

## 完成后更新

- `context.json`：`currentPhase = 归档交付`，`phases.归档交付.done = true`
- 驾驶舱 HTML：锁定为归档状态
- 所有文档标记为最终版本
