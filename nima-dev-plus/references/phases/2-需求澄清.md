# 需求澄清 — 仅完整模式

## 目标

将模糊需求转化为可执行的明确范围，并文档化。

## 产出文档

`1-需求澄清-{storyNameCN}.html`
模板：`references/html-templates/requirement.html`

## 执行步骤

1. 与用户确认需求背景、业务目标、预期效果
2. 确定涉及的功能模块和边界
3. 识别外部依赖和前置条件
4. **确认项目环境探测结果**，如有遗漏补充探测
5. 阅读相关代码仓库结构，确认影响范围
6. 产出 HTML 需求澄清文档

## 全栈模式（devMode=全栈）

需求澄清阶段同时确认前后端范围：

| 维度 | 后端范围 | 前端范围 |
|------|---------|---------|
| 功能边界 | 涉及的 Service、Mapper、接口 | 涉及的页面、组件、路由 |
| 数据边界 | 新增/修改的表和字段 | 前端数据模型、状态字段 |
| 接口边界 | 新增/修改的 API 端点 | 前端调用的接口清单 |
| 依赖关系 | 后端外部服务依赖 | 前端第三方库/组件依赖 |

## 文档内容结构

1. **需求背景** — 为什么要做？解决什么业务问题？
2. **业务目标** — 期望达成的量化或定性目标
3. **需求范围** — 包含 / 不包含
4. **项目环境** — 来自 INIT 阶段的探测结果
5. **技术约束** — 认证框架、协议、兼容性要求
6. **涉及模块** — 功能模块清单
7. **外部依赖** — 其他系统接口、第三方服务
8. **前置条件** — 需要提前准备的事项
9. **验收标准** — 可量化的验收条目
