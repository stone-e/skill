# 筑基 — 初始化（三模式共用）

## 目标

初始化工作空间、探测项目环境、确定开发模式和工作模式、创建双轨制数据文件。

## 执行步骤

### 步骤 0：工作空间检查与初始化

> 每次需求开始前，必须先检查工作空间是否存在。

#### 0.1 检查 story 工作空间

```bash
ls "{storyWorkspace}" 2>/dev/null || echo "NOT_FOUND"
```

**如果返回 `NOT_FOUND`**（首次使用技能）：
1. 向用户展示工作空间初始化引导（见 SKILL.md 工作空间初始化章节）
2. 用户确认后创建目录结构
3. 创建 `.env.json` 模板文件
4. 将工作空间路径保存到用户记忆

**如果目录存在**：进入步骤 0.2

#### 0.2 读取共享环境文件

读取 `{storyWorkspace}/.env.json`，获取已知项目环境信息。

`.env.json` 的核心价值：**让用户用自然语言找需求**。

用户不会说"帮我找 xxx-server 的需求"，他们会说"帮我找 OA 的"或"审批相关的"。

`.env.json` 结构（路径由用户确认后填入，以下为通用示例）：
```json
{
  "workspace": {
    "storyPath": "{用户确认的路径}/story",
    "projectsPath": "{用户确认的路径}/projects"
  },
  "projects": {
    "{projectNameA}": {
      "path": "{用户确认的路径}/projects/{projectNameA}",
      "type": "backend",
      "techStack": {
        "jdk": "17",
        "framework": "Spring Boot"
      },
      "aliases": ["OA", "办公自动化", "审批流", "协同办公"],
      "description": "办公自动化系统，负责审批流、协同办公",
      "requirements": []
    },
    "{projectNameB}": {
      "path": "{用户确认的路径}/projects/{projectNameB}",
      "type": "frontend",
      "techStack": {
        "framework": "Vue 3 + Vite + TypeScript"
      },
      "aliases": ["门户", "Portal", "前台", "Web端"],
      "description": "企业门户前端，提供起始页、常用工具",
      "requirements": ["20260701-StickyNote"]
    }
  },
  "updatedAt": ""
}
```

> ⚠️ 以上路径中的 `{用户确认的路径}` 是占位符，实际值由用户在初始化时确认。
> 不同操作系统路径格式不同（Windows: `D:/my-workspace`，macOS/Linux: `~/my-workspace`）。

**.env.json 字段说明**：

| 字段 | 含义 | 示例 | 作用 |
|------|------|------|------|
| `aliases` | 用户可能使用的所有称呼 | `["IAM", "统一认证", "SSO"]` | 当用户说"找 SSO 相关需求"时匹配到这里 |
| `description` | 一句话业务描述 | `"统一认证中心..."` | 帮助 Agent 理解项目是做什么的 |
| `requirements` | 关联的需求 ID 列表 | `["20260320-BizSsoIntegration"]` | 找到关联需求的入口 |
| `techStack` | 技术栈简要信息 | `{...}` | 环境探测参考 |
| `type` | 项目类型 | `backend` / `frontend` / `fullstack` | 分类筛选 |

**匹配逻辑**：
当用户说"帮我找 XX 相关的需求"或"XX 系统的 XXX"时，Agent 应遍历 `.env.json` 的所有 `aliases` 和 `description`，找到匹配的项目，然后列出其 `requirements`。

**如果 `.env.json` 存在且当前需求涉及的项目已在其中**：
- 展示已知环境信息（包括 aliases 和 description），询问用户是否沿用
- 确认 → 跳过完整探测，直接使用已知信息
- 否认 或 新项目 → 执行完整探测并追加到 `.env.json`

**如果 `.env.json` 不存在**：
- 创建模板文件（仅包含 workspace 路径）
- 后续探测结果将追加到该文件

#### 0.3 维护规则

| 操作 | 时机 | 说明 |
|------|------|------|
| 创建 `.env.json` | 首次使用技能 | 初始化工作空间时 |
| 读取 `.env.json` | 每个需求的筑基阶段 | 加速环境探测 |
| 追加新项目 | 发现新项目时 | 探测完成后追加到 `projects` |
| 更新已有项目 | 技术栈变更时 | 更新 `techStack` 和 `lastExplored` |
| 关联需求 | 需求完成时 | 追加 `storyDesc` 到 `requirements` |

### 步骤 1：确定核心变量

从用户描述中提取或推断以下变量：

| 变量 | 推断规则 |
|------|---------|
| `storyNameCN` | 从用户描述中提取，不明确时概括后请用户确认 |
| `storyNameEN` | PascalCase 英文缩写，Agent 建议，用户确认 |
| `storyType` | 默认 `feat`；判断为 Bug 修复时用 `fix` |
| `storyId` | 有平台需求号时直接使用；否则按当前日期 `yyyyMMdd` |
| `storyDesc` | `{storyId}-{storyNameEN}` |
| `storyAuthor` | `git config user.name` 或 email 前缀 |
| `storyBranch` | `{storyAuthor}/{storyType}-{storyDesc}` |

### 步骤 2：环境与记忆优先 — 加载已知项目环境

> 优先级：`.env.json`（项目级共享） > `~/.claude/projects/`（用户记忆） > 完整探测

#### 2.1 从 `.env.json` 加载（最高优先级）

如果步骤 0.2 中已读取到当前项目的已知环境信息：

```
根据 .env.json 记录，当前项目的已知环境信息：
  - 项目：{项目名}（{别名1}、{别名2}）
  - 技术栈：{技术栈简要描述}
  - 上次探索：{上次探索时间}（需求：{关联需求}）

是否沿用此环境信息？
[1] 是，直接使用（跳过探测）
[2] 否，重新探测
```

- 用户确认 → 直接写入 `context.json` 的 `projectEnv`，跳过步骤 3
- 用户否认 → 进入步骤 2.2

#### 2.2 从用户记忆加载（次优先级）

如果 `.env.json` 中没有当前项目信息：
1. 读取用户记忆文件（`~/.claude/projects/{projectPath}/memory/`），查找项目技术栈相关记忆
2. **如果找到记忆**：展示给用户确认
   - 确认 → 直接写入 `context.json` 的 `projectEnv`，并同步追加到 `.env.json`
   - 否认 → 执行步骤 3 完整探测
3. **如果未找到记忆**：执行步骤 3

### 步骤 3：项目环境探测

扫描项目根目录 `pom.xml` / `build.gradle` / `package.json`，识别：

| 维度 | 探测方式 |
|------|---------|
| JDK 版本 | `pom.xml` → `<java.version>` 或 `maven-compiler-plugin` |
| Spring Boot 版本 | parent POM 或 dependency management |
| ORM 框架 | mybatis-spring-boot / mybatis-plus / jpa |
| 业务基础框架 | continew-starter / jeecg-boot / 自研 |
| 工具库 | Lombok / Hutool / Guava |
| 数据库类型 | MySQL / PostgreSQL / Oracle |

### 步骤 4：前端项目检测与开发模式问询

1. 在项目根目录及上级目录查找前端项目特征文件：
   - `package.json`（含 Vue/React/Angular 依赖）
   - `vue.config.js` / `vite.config.ts` / `next.config.js`
   - 常见前端目录：`frontend/`、`web/`、`ui/`、`admin-ui/`
2. **检测到前端项目** → 展示路径和技术栈，询问用户选择全栈/后端模式
3. **未检测到** → 自动设为后端模式
4. 将 `devMode` 保存到 `context.json` 并同步到用户记忆

### 步骤 5：模式确认与阶段推进（⚠️ 必须与用户交互确认）

1. 评估改动范围 → 确定工作模式（执行修改 / 快速 / 完整）
2. **向用户展示评估结果和推荐模式，等待用户确认**：
   ```
   根据您的需求描述，我评估如下：
   - 改动范围：约 X 个文件，涉及 [模块列表]
   - 推荐模式：[执行修改 / 快速 / 完整]
   - 开发模式：[后端 / 全栈]
   
   是否按推荐模式执行？或有其他偏好？
   ```
3. 将探测结果写入 `context.json` 的 `projectEnv`
4. **创建需求分支**：
   - 执行修改模式：询问是否需要创建分支
   - 快速/完整模式：默认创建分支
5. 创建 `storyDir` 目录：`{storyWorkspace}/{storyDesc}/`

### 步骤 6：创建双轨制数据文件

1. **创建 context.json**：使用 `references/html-templates/context.json` 模板
   - 填入核心变量、projectEnv、初始 phases 结构
   - `currentPhase` 设为下一阶段
   - `createdAt` 和 `updatedAt` 设为当前时间

2. **创建驾驶舱 HTML**：使用 `references/html-templates/dashboard.html` 模板
   - 填充①元数据区
   - 填充②进度仪表盘（筑基标记为完成）
   - 其余区域为待填充状态

### 步骤 7：关键词关联搜索与知识吸收

#### 7.1 关键词提取

从当前需求描述中提取**需求特征关键词**，遵循以下规则：

**关键词的本质**：未来做同类需求时，用于快速定位需求背景和关联知识。

**应该提取的**（需求特征）：
- 业务域：需求属于哪个业务领域（如：起始页、工作台、订单管理）
- 功能模式：需求采用什么功能模式（如：工具嵌入、弹窗交互、实时保存、数据导出）
- 用户场景：面向什么用户场景（如：个人效率、快速操作、批量处理）
- 业务概念：需求涉及的核心业务概念（如：便签、发票、审批、报表）

**不应该提取的**（实现细节）：
- 技术栈：Vue3、React、Spring Boot、JWT、MyBatis-Plus
- 实现细节：防抖、节流、Composable、逻辑删除
- 项目路径：{项目技术名}（如 web-server、boot-module）
- 模块路径：{模块名}（如 tools、start-page）

**正确 vs 错误示范**：

| 维度 | ✅ 正确（需求特征） | ❌ 错误（实现细节） |
|------|-------------------|-------------------|
| 业务域 | 起始页、工作台、个人效率 | {项目技术名}、{模块名} |
| 功能模式 | 工具嵌入、弹窗交互、实时保存 | 防抖、Composable、JWT认证 |
| 用户场景 | 快速操作、轻量记录、备忘 | 用户隔离、权限控制 |
| 业务概念 | 便签、发票打印、快捷入口 | {英文类名}、{英文模块名} |

#### 7.2 关联需求搜索

1. **搜索已有需求空间的 `context.json` 的 `keywords` 字段**（机器数据，非 HTML）
   - 遍历 `{storyWorkspace}/*/context.json`
   - 对比 `keywords` 的各维度
   - 计算关键词交集

2. **如果发现关联需求**：
   - 读取关联需求的 `context.json` 和总结文档（`SUM-总结-*.html`）
   - **主动吸收关联知识**：理解关联需求的背景、方案、经验教训
   - 向用户展示关联结果：
   ```
   发现以下关联需求空间：
    - [门户便签功能] (20260701-StickyNote) — 共享关键词：起始页、工具嵌入、弹窗交互
      关联点：同为起始页常用工具，可复用工具注册模式和弹窗管理方案
   
   是否参考此需求的上下文？Agent 已吸收其设计经验。
   ```

3. 将关联结果保存到 `context.json` 的 `relatedStories`

> ⚠️ 关键词是给 Agent 做知识图谱查询用的机器数据，存储在 context.json 中，不生成独立 HTML。

### 步骤 8：记忆持久化

将完整探测结果保存到用户记忆：

```
---
name: project-env-{projectName}
description: 项目环境特征 - 技术栈、框架版本、开发模式
metadata:
  type: project
---

项目名称：{projectName}
技术栈：JDK {version} + Spring Boot {version} + {orm} + {businessFramework}
工具库：{toolkit}
数据库：{databaseType}
前端技术栈：{frontendStack}（如有）
开发模式：{devMode}（后端 / 全栈）
项目路径：{projectRoot}
最后更新：{date}
```

### 步骤 9：更新共享环境文件

将当前需求探测到的项目信息更新到 `{storyWorkspace}/.env.json`：

1. **如果是新项目**（`.env.json` 中不存在）：
   - 追加到 `projects` 字段
   - 记录 `path`、`type`、`techStack`、`aliases`、`lastExplored`、`requirements`

2. **如果是已有项目**（`.env.json` 中已存在）：
   - 更新 `techStack`（如有变更）
   - 更新 `lastExplored` 为当前时间
   - 追加当前 `storyDesc` 到 `requirements` 数组

3. 更新顶层 `updatedAt`

## 完成后更新

- `context.json`：`currentPhase` 设为下一阶段（执行修改模式→`执行修改`，快速模式→`现状分析`，完整模式→`需求澄清`）
- 驾驶舱 HTML：筑基节点标记为 ✅ 完成
- `.env.json`：更新项目信息和关联需求
- `updatedAt` 刷新
